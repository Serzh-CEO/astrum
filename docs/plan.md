Ядро:
1. Аккаунты
Регистрация и вход
Профиль: имя, смена пароля

2. Проекты
Создание, редактирование, удаление
Список проектов на главной
Поиск по названию
Теги или категории (простой фильтр)

3. Гибкая структура проекта (главная фишка)
Владелец создаёт типы блоков («Сцены», «Персонажи», «Локации» и т.д.)
Два вида блоков:
документ (упорядоченный текст: главы, сцены);
карточка (поля, которые задаёт владелец).
Элементы внутри блока: создание, редактирование, удаление, перестановка порядка
Готовые шаблоны проекта («Сценарий», «Роман»), чтобы не собирать структуру с нуля

4. Редактор
Готовый редактор , без написания своего
Автосохранение
Заголовки, жирный, курсив, списки

5. Версии
Снимок документа вручную и автоматически
История версий
Восстановление старой версии

6. Совместная работа 
Приглашение участников в проект
Роли: владелец, редактор, читатель
Проверка прав на каждом запросе
Защита от перезаписи чужих правок (оптимистичная блокировка: предупреждение, если кто-то сохранил раньше)

7. Экспорт
Markdown и/или PDF

8. Инженерная обвязка
Тесты (pytest) на права, версии и структуру
Docker и docker-compose
CI (GitHub Actions)
Swagger-документация API
README со схемой БД и описанием решений
Деплой с живой ссылкой


Порядок реализации:
1)Аккаунты и проекты
2)Типы блоков и элементы (самая сложная часть модели данных, лучше делать, пока проект маленький)
3)Редактор и автосохранение
4)Версии
5)Участники и роли (права проще встроить заранее: добавлять их в конце в готовую систему дороже)
6)Экспорт
7)Тесты, Docker, CI и деплой (тесты лучше писать по ходу, а не в конце)
